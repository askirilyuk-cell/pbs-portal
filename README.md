# Портал ИСМ ПБС — производственный модуль (MVP-1)

Производственный модуль портала ИСМ ООО «Петробалт Сервис» на **NocoDB**,
self-hosted на **Synology DS725+** (Container Manager, PostgreSQL).
Рядом — **n8n** (автоматизации), **Gotenberg** (HTML→PDF), **Metabase** (аналитика).

Реализует **MVP-1** (раздел 9 ТЗ): Заказы + Позиции + справочники
(Участки / Типы операций / Параметры) + Задачи на участки + печать ПЗ.
Маршруты/Операции — 2-я итерация; контроль (Ф.3/4/5) — 3-я.

Источники: `docs/ТЗ — Производственный модуль…md`,
`docs/Модель производства…md`, `docs/Техническое решение…md`,
справочники сидируются из `docs/Ф.1–П Справочники производства.xlsx`.

## Структура

```
docker-compose.yml          PostgreSQL + NocoDB + n8n + Gotenberg + Metabase
.env.example                переменные/секреты (скопировать в .env)
scripts/
  postgres-init/            автосоздание БД n8n и metabase
  export_seed_from_xlsx.py  генератор seed-данных из Ф.1–П
nocodb/
  lib/nocodb-client.mjs     клиент Meta+Data API
  schema/                   schema.json + build-schema.mjs (8 таблиц, словари, связи)
  seed/                     seed.mjs + data/*.json (справочники + демо-ПЗ)
  views/build-views.mjs     реестр ПЗ, очередь мастера, карта задачи (планшет)
print/
  pz-template.html          печатный вид ПЗ (Ф.1–П.2)
  render-pz.mjs             NocoDB → HTML → Gotenberg → PDF
n8n/workflows/              автонумерация ПЗ, агрегация статусов, параметры задачи
```

## Схема данных (8 таблиц)

| Таблица | Назначение |
|---|---|
| **Заказы** | 1 запись = 1 ПЗ (Ф.1–Д.1 + Ф.1–П.2 разд. 1/2/4/5) |
| **Позиции** | номенклатура заказа (Ф.1–П.2 разд. 3) |
| **Задачи на участки** | карты задач (Ф.2–Д.1 / Ф.14) |
| **Значения параметров задачи** | блок параметров по типу операции (§12 модели) |
| **Участки** | справочник УЧ-01…УЧ-17 (Ф.1–П) |
| **Типы операций** | 16 типов ОП-… (Ф.1–П) |
| **Параметры типов** | 51 параметр по типам (Ф.1–П) |
| **Сотрудники** | роли: Технолог/ДпП/Менеджер/Мастер/Рабочий/ОТК |

Связи: Заказы 1—N Позиции 1—N Задачи 1—N Значения параметров ·
Задачи N—1 Участок / Тип операции / Сотрудник(исполнитель) ·
Типы операций N—1 Участок · Параметры N—1 Тип операции ·
Сотрудник(ответственный) 1—N Заказы.

## Развёртывание на NAS

**Координаты** (из плана развёртывания): SSH `aleksandr-kirilyuk@192.168.1.10:22`,
рабочая директория `/volume1/docker/`, DSM `https://192.168.1.10:5001`.

### 1. Подготовка

```bash
# на NAS: скопировать репозиторий в /volume1/docker/pbs-portal
cd /volume1/docker/pbs-portal
cp .env.example .env
# заполнить пароли/секреты в .env:
#   openssl rand -hex 32   → NC_AUTH_JWT_SECRET, N8N_ENCRYPTION_KEY
chmod +x scripts/postgres-init/01-create-databases.sh
```

### 2. Запуск контейнеров

Через **Container Manager** (Project → импорт `docker-compose.yml`) или по SSH:

```bash
docker compose up -d
docker compose ps          # все healthy
```

Доступ (прямые порты, MVP):

| Сервис | URL |
|---|---|
| NocoDB | http://192.168.1.10:8080 |
| n8n | http://192.168.1.10:5678 |
| Metabase | http://192.168.1.10:3000 |
| Gotenberg | http://192.168.1.10:3001 (внутренний) |

Первый вход в NocoDB — создать суперадмина.

### 3. Схема + сидинг + представления

С машины с доступом к NocoDB (или на NAS, если есть Node ≥18):

```bash
cd nocodb
# токен: NocoDB UI → аккаунт → Tokens; или используйте NC_EMAIL/NC_PASSWORD
export NC_URL=http://192.168.1.10:8080
export NC_TOKEN=<api-token>
npm run all        # schema → seed → views
```

После `schema` появится `nocodb/.state/schema-map.json` — оттуда возьмите
`baseId` для `NC_BASE_ID`.

### 4. n8n (автоматизации)

1. Вписать `NC_TOKEN` и `NC_BASE_ID` в `.env`, затем `docker compose up -d n8n`.
2. Импортировать и активировать workflow, подключить вебхуки NocoDB —
   подробно в [`n8n/README.md`](n8n/README.md).

### 5. Печать ПЗ

```bash
cd <repo>
export NC_URL=http://192.168.1.10:8080 NC_TOKEN=<token>
export GOTENBERG_URL=http://192.168.1.10:3001
node print/render-pz.mjs ПЗ-2026-001 ПЗ-2026-001.pdf
```

(В проде печать удобно вынести в отдельный n8n-workflow: вебхук → этот рендер → файл в досье.)

### 6. Metabase

UI `:3000` → подключить источник: PostgreSQL `postgres:5432`, БД `nocodb`,
пользователь/пароль из `.env`. Дашборды по реестру ПЗ и очереди задач.

## Бэкап (план развёртывания, Фаза A)

- `pg_dump` по cron + Hyper Backup папки `/volume1/docker/`.
- Тест восстановления обязателен.

## Обновление seed-данных

Справочники меняются в `docs/Ф.1–П…xlsx` →
`python scripts/export_seed_from_xlsx.py` → `npm run seed` (идемпотентно).

## Что НЕ входит в MVP-1

- **Маршруты + Операции** (генерация задач из маршрута) — 2-я итерация.
  В «Задачах» оставлено текстовое поле «Операция (№ МК / № оп.)» как задел.
- **Контроль** (Ф.3 входной / Ф.4 приёмочный / Ф.5 несоответствие) — 3-я итерация.
- **Caddy / HTTPS** — добавляется отдельным шагом (Фаза A плана развёртывания).
- **Оборудование** (Ф.1–О.3.2) как таблица — пока текстовое поле в «Задачах».

## Известные предположения / риски

- Скрипты схемы используют **NocoDB Meta API v1** (`/api/v1/db/meta/...`).
  Самая версозависимая операция — создание связей (`createLink` в
  `nocodb/lib/nocodb-client.mjs`) и привязка строк (`/mm/` в n8n `03-…`).
  При смене контракта NocoDB правьте только эти места.
- Реестр `Ф.1–Д.1 Реестр ПЗ.xlsx` в исходниках **без live-строк** — демо-ПЗ
  (`ПЗ-2026-001/С004/013`) сгенерированы синтетически для проверки видов и печати.
