# Модель производства — маршруты и карты задач

> **TL;DR.** Целевая модель производственной документации для портала (планшеты на участках) и для пересборки §6 ДП-Д.1. Уходим от мышления «формами» к **модели данных**: один сквозной маршрут на изделие → операции → карты задач на участок. Формы остаются утверждаемыми, но это *виды* данных, а не листы бумаги.

## 1. Решения, зафиксированные 2026-06-11

- **Портал-first.** МК и задания живут на портале; рабочий открывает их с планшета на участке, печать — не цель.
- **Форма = вид данных**, но **утверждаемые формы остаются** (маршрут, карта задачи на участок, ПЗ).
- **Маршрут — на изделие/компонент** (сквозной, мастер-документ технолога). На участок идут **карты задач**, привязанные к маршруту.
- **Универсальную МК (Ф.13–Д.1) — убираем** как сомнительную сущность. Для нетиповой/разовой оснастки — лёгкий путь: **ПЗ + чертёж** (кол-во + подпись отправившего), вводится с планшета.
- **Линейки (БМ/РТИ/ПВО/МО) и КОМ/СБР — это атрибуты**, а не отдельные формы.

## 2. Трёхслойная модель

| Слой | Что это | Привязка | Кто работает |
|---|---|---|---|
| **Маршрут (МК)** | Сквозная последовательность операций изделия/компонента: КАК производить | на **изделие/компонент** | Технолог (мастер-документ) |
| **Карта задачи на участок** | Операция этого маршрута, выданная на участок: что делать здесь и сейчас | на **операцию/участок** (генерится из маршрута + ПЗ) | Рабочий (планшет), Мастер |
| **ПЗ (производственный заказ)** | ЧТО / СКОЛЬКО / КОГДА + ссылка на маршрут | на **партию/заказ** | ДпП / Мастер |

Маршрут — один. Карты задач — много (по числу операций), и **на каждом участке они единообразны** (твоя идея верна — именно на этом уровне). Сквозной маршрут при этом сохраняется для технолога и мастера.

## 3. КОМ/СБР и линейки — атрибуты, не формы

- **КОМ/СБР** — структурный атрибут маршрута: маршрут делает **компонент** (один выход) или **собирает** изделие из компонентов.
- **Продуктовая линейка** — это **набор типов операций**. У RTI есть операция «вулканизация» со своими параметрами, у биметалла — «наплавка», у резины — «вальцевание смеси». «Спецблоки линеек» Ф.6–Ф.10 превращаются в **типовые операции с типовыми полями**.
- Таким образом §6.8 (линейки) и §6.9 (КОМ/СБР) ДП-Д.1 сводятся в **одну** модель: маршрут (КОМ/СБР) из операций, каждая операция — своего типа.

## 4. Утверждаемые формы после пересборки

| Форма | Назначение | Статус идеи |
|---|---|---|
| **Карта маршрута (МК)** | сквозной маршрут изделия/компонента | оставить, переопределить как «маршрут из операций» |
| **Карта задачи на участок** | операционная карта для рабочего (планшет) | **новая ключевая форма**; единый шаблон с блоками по типу операции |
| **ПЗ (Ф.1–П.2 «Производственный заказ»)** | что/сколько/когда + ссылка на маршрут; также лёгкий путь для оснастки (ПЗ + чертёж) | оставить |
| ~~Универсальная МК (Ф.13–Д.1)~~ | — | **убрать**, заменена связкой ПЗ + чертёж |
| Спецформы МК Ф.6–Ф.10 | биметалл/РТИ/ПВО/МО/ЗАГ | пересобрать как **типы операций** внутри единой модели (не отдельные формы) |

> Вопрос на обсуждение: «Карта задачи» — **один утверждённый шаблон** с секциями по типу операции (рекомендую — меньше форм, дружелюбно к порталу) **или** отдельная утверждённая форма под каждый участок. Твоя фраза «форма МК по каждому участку» допускает оба; единый типизированный шаблон даёт то же единообразие на участке, но проще в сопровождении.

## 5. Поля «Карты задачи на участок» (черновик)

Что должно быть в утверждённой форме задания (по твоим словам — «чем руководствоваться, связанные РИ, какие материалы взять»):

- **Основание:** № заказа / ПЗ, приоритет, срок.
- **Изделие/деталь:** наименование, обозначение, чертёж (ссылка), применимость.
- **Операция:** № в маршруте, тип операции, участок (Ф.1–П), оборудование (Ф.1–О.3.2).
- **Чем руководствоваться:** связанные **РИ** (по типу операции — связь с целью К-1) и **ИОТ** (охрана труда).
- **Входящие материалы/компоненты:** что взять со склада, кол-во, № партии/МК-источника (**прослеживаемость**), отметка кладовщика.
- **Режимы/параметры** (по типу операции): для наплавки — свои, для токарки — свои, для вулканизации — свои.
- **Контроль:** тип (С — самоконтроль / ОТК), что мерить, СИ.
- **Нормы:** норма времени.
- **Отметки выполнения:** исполнитель, факт. время, подпись (или цифровая отметка на планшете), подпись ОТК.

## 6. Виды (одни данные — разные экраны)

- **Технолог:** весь маршрут изделия (создаёт/правит).
- **Мастер участка:** очередь операций своего участка по всем заказам.
- **Рабочий (планшет):** одна операция за раз, единый layout участка, отметка о выполнении.

## 7. Лёгкий путь — разовая оснастка / нетиповое

Без полного маршрута: **ПЗ + чертёж**. На чертеже/в ПЗ — кол-во и подпись отправившего; вводится с планшета. Это закрывает кейс «надо сделать мелкую оснастку» без избыточной универсальной МК.

## 8. Что меняем в ДП-Д.1

§6 переписать под эту модель: маршрут = операции (КОМ/СБР как атрибут, линейки как типы операций); карта задачи на участок как утверждаемая форма; ПЗ + чертёж для нетипового; убрать универсальную МК. Процедура описывает **логику** — носитель (форма сейчас / портал потом) вторичен, переделывать при запуске портала не придётся. Мелкие правки кодов (Ф.1→реальные, битые коды) — заодно.

## 11. Типы операций (ведущий справочник)

Каждая операция в маршруте имеет **тип**; тип задаёт участок, связанную РИ (цель К-1) и набор типовых параметров в карте задачи.

| Тип операции | Участок (Ф.1–П) | РИ | Типовые параметры |
|---|---|---|---|
| Заготовка / раскрой | УЧ-16 | план. | размер реза, кол-во, припуск |
| Токарная обработка | УЧ-10 | план. | режимы (n, S, t), инструмент, программа ЧПУ, припуски |
| Фрезерная ЧПУ | УЧ-09 | РИ.19–Д.1 (ЧПУ) | программа ЧПУ, инструмент, режимы |
| Фрезерная (универсал) | УЧ-08 | план. | режимы, инструмент |
| Электроэрозионная | УЧ-14 | план. | программа, проволока, режимы |
| Плоское шлифование | УЧ-11 | план. | припуск, Ra, диск |
| Слесарные / сверление / сборка | УЧ-06 | план. | Ø/глубина, резьба, состав сборки, момент затяжки |
| Наплавка | УЧ-03 | план. | материал наплавки, ток/U, число слоёв, толщина, HV |
| Плазменная резка | УЧ-04 | РИ.5–Д.1 | толщина, программа раскроя, скорость |
| Вальцовка листа | УЧ-02 | РИ.11–Д.1 | Ø обечайки, толщина, число проходов |
| Сварка | УЧ-05 | план. | тип (MIG/MAG, TIG, РДС), материал, режим |
| Дробеструйная подготовка | (DXQ3510) | план. | время, степень очистки |
| Окраска | УЧ-07 | план. | покрытие, толщина, число слоёв |
| Прессование / литьё РТИ | УЧ-12 | план. | способ (прямое/инъекц.), T, P, время вулканизации, пресс-форма |
| Вальцевание резиновых смесей | УЧ-13 | план. | рецепт, зазор, число пропусков |

> Существуют РИ.5–Д.1 (плазма), РИ.11–Д.1 (вальцовка), РИ.19–Д.1 (ЧПУ FangLing). Остальные — план. (это и есть цель К-1: первичные РИ на 14 основных участков).

## 12. Карта задачи на участок — поля (единый типизированный шаблон)

**Общие блоки (всегда):**
1. **Шапка:** № карты задачи, № ПЗ/заказа, дата выдачи, приоритет, срок.
2. **Изделие/деталь:** наименование, обозначение, чертёж (ссылка), применимость.
3. **Операция:** № в маршруте, **тип операции** (§11), участок (Ф.1–П), оборудование (Ф.1–О.3.2).
4. **Чем руководствоваться:** связанные **РИ** (по типу) и **ИОТ**, чертёж, технологические указания.
5. **Входящие материалы/компоненты:** что взять, кол-во, № партии/сертификата/МК-источника (**прослеживаемость**), отметка склада.
6. **Контроль:** тип (С — самоконтроль / ОТК), что мерить, СИ, допуски.
7. **Норма времени.**
8. **Отметки выполнения:** исполнитель, факт. кол-во, факт. время, подпись/цифровая отметка, подпись ОТК.

**Блок параметров по типу операции** (подставляется из §11): наплавка — материал/ток/слои/HV; токарная/фрезерная — режимы/инструмент/программа; вулканизация — T/P/время/форма и т.д.

> На планшете рабочий видит блоки 1–8 в едином layout; блок параметров меняется по типу операции — отсюда «единообразие на участке» без 14 отдельных форм.

### 13.3 Связи

- **Заказы 1 — N Позиции** (по № ПЗ).
- **Позиции 1 — N МК** (Ф.3–Д.1) и **1 — N Задачи на участки** (Ф.2–Д.1) — по позиции/изделию.
- Статус ПЗ = агрегат статусов позиций; статус позиции = агрегат отметок выполнения карт задач (§12).
- Полная цепочка прослеживаемости: **Заказы → Позиции → МК / Задачи на участки → отметки выполнения**.
