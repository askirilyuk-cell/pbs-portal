# ТЗ — Производственный модуль портала ИСМ ПБС (схема для Claude Code)

> Консолидированная схема данных, выведенная из утверждённых процедуры **ДП–Д.1–1.1** и реестров/форм на NAS. Это вход для Claude Code: построить производственный модуль портала на NocoDB. Проектная логика — в [[Модель производства — маршруты и карты задач|Модели производства]]; стек/развёртывание — в [[Техническое решение и план развёртывания]].

## 1. Цель и рамка MVP

Оцифровать производственный цикл: **Заказ (ПЗ) → Позиции → Маршрут → Операции → Задачи на участки → Контроль**. Формы остаются как печатные виды (генерация из данных). Рабочий на участке работает с планшета.

**MVP-1 (первая итерация):** Заказы + Позиции + Справочники (участки/типы операций/параметры) + Задачи на участки + печать ПЗ. Маршруты/операции — 2-я итерация; контроль (Ф.3/Ф.4/Ф.5) — 3-я.

## 2. Стек (уже выбран)

NocoDB (БД+API+UI) + n8n (автоматизации) + Gotenberg (HTML→PDF печать) + Metabase (аналитика), self-hosted на **Synology DS725+** (Container Manager), PostgreSQL. Детали — в заметке развёртывания.

### 3.6. Справочники — источник: Ф.1–П «Справочники производства» (сидировать)
- **Участки** (УЧ-01…УЧ-17): code, name, type (основной/вспомогательный), equipment, responsible.
- **Типы операций** (16, ОП-…): code, name, section_id (FK), ri_ref. Список: ЗАГ, ТОК, ФРЧ, ФРУ, ЭЭО, ШЛ, СЛ, НАП, ПЛ, ВАЛ, СВ, ДРО, ОКР, ПРС, ВРС, ОТК.
- **Параметры типов** (52): op_type_id (FK), param, unit, value_type, required.

### 3.7. Контроль — источники: Ф.3 / Ф.4 / Ф.5 (3-я итерация)
- **Входной контроль (Ф.3):** id, num, date, supplier, material, mark, qty, date_made, shelf_life, checks(sub), verdict (Годен/Не годен/С замечаниями), signs.
- **Приёмочный контроль (Ф.4):** id, num, date, pz/pos, mk, product, drawing, qty, measures(sub: param/nominal/tol/fact/si/result), verdict (Годен/С отклонением/Не годен), signs.
- **Несоответствие (Ф.5):** id, num_np, stage, pz/mk, product, qty_np, description, cause, decision (Исправить/Принять с откл./Утилизировать/Вернуть пост.), corrective_action, effectiveness_check. Обработка — по ДП–У.2.

## 4. Связи (ER)

- **Заказы 1 — N Позиции** (pz_id)
- **Позиции N — 1 Маршрут** (route_id; может быть null — лёгкий путь)
- **Маршруты 1 — N Операции** (mk_id)
- **Операции 1 — N Задачи на участки** (op_id)
- **Задачи N — 1 Участок / Тип операции / Оборудование**
- **Типы операций N — 1 Участок**; **Параметры N — 1 Тип операции**
- **Контроль:** Приёмочный → Позиция/Задача (финал); Несоответствие → Позиция/Задача/Материал; Входной → приёмка материала.
- **Агрегация статусов:** Задачи → Позиция → Заказ (n8n или rollup).

## 5. Представления (views)

- **Технолог:** Маршруты + Операции (CRUD), справочники типов операций/параметров.
- **Мастер участка:** очередь Задач своего участка (фильтр section_id + status), приоритеты.
- **Рабочий (планшет):** одна Задача, единый layout участка, блок параметров по типу, кнопки «Старт / Выполнено», отметка самоконтроля/ОТК.
- **ДпП / ПРК:** Реестр ПЗ (заказы), статусы, аналитика (Metabase).

## 6. Печатные виды (Gotenberg, HTML→PDF)

Генерировать из данных: **ПЗ** (Ф.1–П.2), **Маршрутная карта** (Ф.13), **Карта задачи** (Ф.14), акты **Ф.3 / Ф.4 / Ф.5**. HTML-шаблоны Ф.13/Ф.14 уже есть в проектной папке.

## 7. Автоматизации (n8n)

- Авто-нумерация ПЗ (ПЗ-ГГГГ-NNN, сквозная по году) и МК (МК-КОМ/СБР-ГГГГ-NNN).
- Агрегация статусов: Задачи → Позиция → Заказ.
- Уведомления (Bitrix24 / email) при размещении ПЗ и завершении задач.
- Генерация PDF досье при размещении/завершении.
