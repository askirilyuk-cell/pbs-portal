# Портал ИСМ ПБС — Техническое решение и план развёртывания

> **TL;DR:** Закрыт открытый вопрос §8 карточки проекта (стек и хостинг). Платформа строится **self-hosted на Synology DS725+** в Container Manager. Ядро — **NocoDB** (база-источник истины + русские формы для планшета), слой-«клей» — **n8n** (генерация документов из бланков ИСМ, раскладка файлов по папкам, интеграции, AI), плюс **Gotenberg** (PDF) и **Metabase** (дашборды). Разворачиваем фазами; первый видимый результат — реестр документации ИСМ и форма приёмки материалов. Полный сравнительный отчёт по платформам — см. артефакт чата от 2026-06-03 (NocoDB / Baserow / Teable / Budibase / Appsmith / ToolJet / Directus / Paperless-ngx).

## 1. Выбранный стек

| Слой | Инструмент | Роль | Лицензия / стоимость |
|---|---|---|---|
| База + формы | **NocoDB Community** | Реестры, формы для планшета (фото, чекбоксы, комментарии, QR/ШК-поля), роли, выгрузка xlsx для аудита | Fair-code, бесплатно для внутр. использования |
| Хранилище БД | **PostgreSQL** | Мастер-данные NocoDB (НЕ SQLite — чтобы Metabase читал ту же базу) | Open source |
| Клей / автоматизация | **n8n** | Генерация docx/xlsx из шаблонов, раскладка файлов по SMB-папкам ИСМ, интеграция с Bitrix24, AI-ноды | Fair-code, бесплатно self-hosted |
| Генерация документов | **Carbone** (нода n8n) + **Gotenberg** | Рендер брендированных бланков ИСМ в .docx/.xlsx, конвертация в PDF | Carbone Community — бесплатно для внутр. использования |
| Дашборды | **Metabase** | Управленческая аналитика по реестрам (вход в анализ ДП-Л.2.2) | Open source, русский UI |
| Реверс-прокси | Caddy / встроенный DSM | HTTPS, единая точка входа | — |
| OCR-архив (опц.) | **Paperless-ngx** | OCR входящих документов на материалы и сертификатов | Open source |

**Почему так:** NocoDB — единственный кандидат с настоящим русским UI + нативными формами с вложениями + типами QR/штрихкод в бесплатной версии. Его слабые места (нет бесплатных дашбордов, нет генерации брендированных документов, нет раскладки файлов по ФС) ровно те, что закрывает n8n. Никакой no-code-инструмент не умеет нативно отдавать корректный .docx по корпоративному бланку — поэтому генерация документов всегда через n8n+Carbone.

**Главный риск стека:** в NocoDB CE закрыты дашборды, PDF-экспорт Page Designer и кнопки с JS-автоматизацией (они в платном Enterprise). Архитектура обходит это через n8n + Metabase. Сверять гейтинг функций с конкретной версией при установке.

## 2. Железо (DS725+)

- CPU AMD Ryzen R1600 — **2 ядра / 4 потока**. ОЗУ из коробки **4 ГБ**, расширяется до 32 ГБ.
- **Обязательно перед Фазой B:** нарастить ОЗУ до **16 ГБ минимум** (в идеале 32 ГБ, 2×16). На 4 ГБ стек будет задыхаться.
- Нет слота PCIe → 10GbE недоступен (не критично). Требуются диски из списка совместимости Synology.
- AI крутится на **внешнем API** (локально LLM не поднять) — хост не грузит. Для чувствительных данных держать в уме российские API (GigaChat, YandexGPT) наряду с OpenAI/Anthropic.

## 6. Открытые вопросы / на потом

- Авторизация: локальные пользователи NocoDB на старте; AD/LDAP/Bitrix SSO — позже (SSO в NocoDB платный).
- Сканирование QR/ШК камерой прямо в форме не нативно → USB/BT-сканер (как клавиатура) или мини-страница сканирования.
- Реестр чертежей расширяет скоуп за пределы чистого ИСМ (это КД-инфраструктура). Решить — отдельный реестр в том же рабочем пространстве или связка с проектом [[../Реестр ПФ и изделий прессования/_О проекте|Реестр ПФ и изделий прессования]].
- Снапшоты процедур: Александр параллельно согласовывает и грузит процедуры на NAS + делает их снапшоты в vault. Vault = память и снимки документов; портал = источник записей (правило R4 карточки).
- Выбор AI-API (внешний РФ vs зарубежный) — по чувствительности данных конкретного кейса.
